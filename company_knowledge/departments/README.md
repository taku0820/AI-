# 担当チーム（departments）について

このフォルダは、[`company_knowledge`](../README.md) 資料室の一部として、
運用責任者・ROOM担当・note担当・Pinterest担当・分析担当という5つの担当ごとの
仕事マニュアルをまとめたものです。全社共通のルールは資料室の親フォルダ
（[`00_company_rules.md`](../00_company_rules.md) など）にまとまっているので、
このフォルダは「そのルールを、担当ごとの具体的な仕事の流れに落とし込んだもの」と
位置づけてください。

## 担当チームの目的

AI Hive OS では、業務の種類ごとに「運用責任者」「ROOM担当」「note担当」
「Pinterest担当」「分析担当」という役割を仮想的に分けています（役割の全体像は
[`03_roles.md`](../03_roles.md) を参照）。担当を分けることで、それぞれが
何をきっかけに動き、何を確認し、何を成果物として残すのかを明確にし、誰が見ても
同じ基準で提案・記録ができるようにすることが、このフォルダの目的です。

## 利用者本人が最終承認者であること

各担当ファイルに書かれている作業手順や成果物は、あくまで提案・下書き・記録です。
どの担当の作業結果についても、それを採用するかどうか、外部に公開するかどうかを
最終的に決めるのは、常に利用者本人です。担当が自分自身の判断だけで何かを確定させる
ことはありません。

## 各担当は提案・下書き・記録までを担い、投稿・公開・送信・ログイン・削除は行わないこと

運用責任者・ROOM担当・note担当・Pinterest担当・分析担当のいずれも、行ってよいのは
次の範囲までです。

- 提案（次にやること、候補となるテーマ・ジャンルなど）
- 下書き（記事、投稿文、紹介文など）
- 記録（確認した数字、判断の経緯など）

楽天ROOM、note、Pinterest、Threads、楽天アフィリエイトなど外部サービスへの
実際の投稿・公開・送信・ログイン・削除は、どの担当も行いません。これは
[`00_company_rules.md`](../00_company_rules.md) に定める全社共通ルールであり、
担当チームのどのファイルもこのルールを上書きすることはできません。

## 担当間で数字や判断を引き継ぐときは、推測せず確認済みの数値だけを使うこと

分析担当が他の担当（ROOM担当・note担当・Pinterest担当）から数字を受け取って
比較・整理する場合や、運用責任者が各担当の状況を確認して優先順位をまとめる場合、
引き継ぐ数字は必ず「実際に確認済みの数値」だけを使います。

まだ確認できていない数字を、確認できたかのように書いたり、それらしい数字を
推測で補ったりすることはしません。未確認の項目は「未確認」として扱い、
[`05_decision_log.md`](../05_decision_log.md) の様式に沿って記録します。
