# 資料室（company_knowledge）について

このフォルダは、AI Hive OS の「資料室」です。会社としての共通ルールと運用知識を、
誰が読んでも同じ基準で理解できるようにファイルとしてまとめています。

## 資料室の目的

AI Hive OS では、複数の担当（ROOM担当・note担当・Pinterest担当・分析担当など）が
それぞれの持ち場で下書きや提案を作ります。担当ごとに判断基準がバラバラだと、
外部への発信内容や数字の扱いに矛盾が生まれてしまいます。

資料室は、そうした矛盾を防ぐために「これだけは全員が守る」というルールと、
各媒体・各役割についての基本知識を、1か所にまとめて置いておく場所です。
画面（ダッシュボード）や自動化の仕組みよりも先に、まずこの資料室を整備することで、
将来どの機能を追加するときも、同じ土台の上で判断できるようにします。

## AIや人が作業前に読むこと

このフォルダ内のファイルは、AI Hive OS に関わる作業（下書き作成、内容確認、
新しい機能の追加検討など）を始める前に、人・AIの両方が目を通すことを想定しています。
とくに [`00_company_rules.md`](00_company_rules.md) は、他のすべてのルールの土台となる
基本方針なので、最初に確認してください。

- 会社全体の基本ルールを知りたいとき: [`00_company_rules.md`](00_company_rules.md)
- 各媒体（ROOM・note・Pinterest・Threadsなど）の役割を知りたいとき: [`01_channels.md`](01_channels.md)
- 投稿・記事づくりの共通ルールを知りたいとき: [`02_content_policy.md`](02_content_policy.md)
- 各担当の役目や権限を知りたいとき: [`03_roles.md`](03_roles.md)
- 確認する数字の定義を知りたいとき: [`04_metrics.md`](04_metrics.md)
- 判断を記録する様式を知りたいとき: [`05_decision_log.md`](05_decision_log.md)

## 資料室 → 自動化 → 運用司令室の3段階構造

AI Hive OS は、次の3段階で少しずつ育てていく方針です。

1. **資料室（このフォルダ）**
   会社の共通ルールと運用知識を、文章として整備する段階です。まだ画面もDBも
   自動投稿機能も変更しません。すべての判断の土台になる「共通の答え合わせ表」を
   作ることが目的です。
2. **自動化**
   資料室に整備したルールをもとに、下書き作成や記録作業など「人が最終確認する
   前段階」の作業を、必要に応じてツール化・半自動化していく段階です。この段階でも、
   外部サービスへの実際の投稿・送信・ログインは自動実行しません。
3. **運用司令室**
   複数の担当AIと人が、資料室のルールを共通言語として使いながら、日々の状況を
   一つの画面で見渡し、次の一手を判断できるようにする段階です。ここでも、実際の
   公開・送信・ログインを最終的に実行するのは人です。

現時点（MISSION 064）は、この3段階のうち「1. 資料室」の整備にあたります。
画面・DB・自動投稿機能への変更は行っていません。

## 実際の外部投稿・送信・ログインは人が最終承認する方針

資料室・自動化・運用司令室のどの段階においても、次の方針は変わりません。

- 楽天ROOM、note、Pinterest、Threadsなどの外部サービスへの実際の投稿・送信・
  ログインを、AIやツールが自動で実行することはありません。
- AIやツールが作るのは、あくまで下書き・提案・記録までです。
- 公開する・しない、送信する・しない、削除するといった最終判断と実行操作は、
  必ず人（利用者本人）が内容を確認したうえで行います。

この方針の詳細は [`00_company_rules.md`](00_company_rules.md) にまとめています。
